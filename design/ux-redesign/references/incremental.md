# Incremental redesign

Use this when the page already exists and people use it. It is the default.

- Keep what people already know where it is: navigation, labels, and where the primary actions sit.
- Fix the problems with the most impact first. Rank changes by impact against effort.
- Make each change work on its own, so it can ship and be judged separately.
- Draw before and after ASCII for each change, with enough of the page around it to place it.
- If the changes keep pointing at the same structural problem, say so and propose moving to radical. Then read [radical.md](radical.md).

In the plan, fill in "Incremental: changes, ranked by impact" and leave out the radical-only sections.

Why: gentle, evolving change usually serves existing users better than a fresh design ([NN/g](https://www.nngroup.com/articles/fresh-vs-familiar-aggressive-redesign/)).
